# genesis

**Полное руководство: [docs/MANUAL.md](docs/MANUAL.md)** — все команды, стол, клавиши, сеть, браузер, C, ограничения.

Минимальный конвейер загрузки своего ядра для x86_64. Гость стартует в `qemu-system-x86_64` и пишет одну строку и в COM1, и на текстовый экран VGA:

```
genesis: kernel booted
```

Дальше на экране и в serial появляется приглашение `genesis>`. С клавиатуры PS/2 можно набрать строку. В ядре, не в userspace, есть команды `help`, `echo`, `clear`, `mem`, `alloc`, `heap`, `ls`, `cat`, `write`, `run`, `spawn`, `ps` и `desktop`. `mem` читает карту памяти Multiboot2. `alloc` и `heap` работают с bump-аллокатором. При первом запуске в образе диска уже лежат `readme` и плоская программа `hello`. `run hello` печатает `hello from program`. Команда `desktop` открывает домашний экран. Кнопки «Память», «Файлы», «Редактор», «Открыть», «Перезагрузка» и «Выключить» открывают один раздел за раз. У раздела есть «Назад» и нет его на домашнем экране. «Память» показывает строку usable. «Файлы» и «Открыть» показывают имена; щелчок запускает программу просмотра по расширению (`vtxt`, `vdocx`, `vimg`, `vpdf`, `vmp4` на диске). В редакторе буквы дописываются в текст, Enter сохраняет `readme`. Перезагрузка снова показывает домашний экран, выключение завершает QEMU. Те же команды есть в строке `genesis>`.

Многозадачность: таймер PIT (100 Гц) переключает задачи ядра по кругу, у каждой свой стек (до 4 задач, задача 0 — сама оболочка). `spawn ticker` запускает программу с диска фоновой задачей: она пять раз печатает `tick` раз в полсекунды и завершается строкой `task 1 done`, а оболочка и часы тем временем работают. `ps` показывает живые задачи и сколько тиков таймера каждая получила. Программа вызывается как `prog(print, sleep)`, где `sleep(n)` ждёт n тиков. Всё работает в кольце 0, без изоляции памяти. Фоновый запуск — `spawn NAME` или `NAME &`.

Мышь PS/2 тащит область за заголовок и меняет размер за правый нижний угол. Область остаётся на экране. Щелчок по телу области выбирает её и переносит жёлтую рамку. Таймер раз в секунду перерисовывает часы (`time HH:MM:SS`), в том числе пока в другой области выполняется `wait`. Клавиши `1`–`4` тоже выбирают область. Остальные символы набираются в выбранной области; Enter выполняет там `mem`, `ls`, `run hello` или `wait`.

`write` и `edit` сохраняют файл на сырой диск QEMU, без FAT. `edit readme` показывает текущий текст, следующая строка заменяет его и сразу пишется на диск. `cat` по-прежнему печатает файл. Первая загрузка с CD записывает ядро на этот же диск и не трогает уже лежащие файлы. Следующий запуск может идти только с диска, без CD. Команда просмотра держит один и тот же образ `build/genesis-disk.img`. Тесты каждый раз берут свой пустой образ, чтобы не мешать друг другу.

Между двумя гостями есть свой протокол Genesis Link. Это не IP и не TCP. Кадр Ethernet с частным ethertype `0x88B5` только несёт пакет внутри QEMU. Заголовок: байты `G` `L`, версия 1, тип `u8`, длина полезной нагрузки `u16`, контрольная сумма `u16`. Типы: ping, pong и text. Два гостя соединяются сокетной сетью QEMU (`listen` и `connect`). `ping` ждёт `pong`, `say TEXT` показывает текст на другой стороне как `link: TEXT`. Кроме этого есть обычный TCP/IP, см. «Сеть (TCP/IP)».

Хостовая часть — CLI на Node.js и TypeScript и одна страница React. CLI собирает ISO, запускает QEMU с таймаутом и возвращает код 0 только если в serial есть маркер. Тесты дополнительно сверяют текстовый экран, клавишу, `help`, память, файлы, программу, щелчок мыши, ход часов, набор в области стола, сохранность файла после перезагрузки и снимок стола. Кнопка «Запустить» показывает этот снимок, а не только журнал COM1. Окно QEMU при просмотре не закрывается само.

QEMU через `-kernel` не принимает 64-битный ELF (`Cannot load x86-64 image, give a 32bit one`). Поэтому образ — CD с GRUB: Multiboot2 передаёт управление 32-битной точке входа, ядро само включает long mode. Если старт обрывается раньше, на COM1 будет `ERR M` (нет Multiboot2), `ERR C` (нет CPUID) или `ERR L` (нет long mode).

### Папки и Grid Store (GBF2)

Диск — Grid Store версии 2 (`GBF2`): до 256 файлов и папок, файл до 1 МБ, путь до 63 символов (имя до 31), образ диска 32 МБ (создаётся разреженным). Раскладка: `/bin` — программы, `/lib` — библиотеки `pkg`, `/docs` — примеры, `/home` — ваши файлы и папка по умолчанию. Приглашение показывает текущую папку: `genesis:/home>`.

```
pwd; ls /; ls /docs
mkdir proj; cd proj; write main.c int main;
cd ..; ls proj; cat proj/main.c
cp proj/main.c /docs; mv /docs/main.c old.c
rm proj/main.c; rmdir proj
run hello        # ищет в текущей папке, потом в /bin
```

Пути абсолютные и относительные, с `.` и `..`; их принимают `cat`, `write`, `rm`, `edit`, `sh`, `run`, `grep`, `>`/`>>`. `rmdir` удаляет только пустую папку. Файлы из `import/` попадают в `/home`. В «Файлах» и «Открыть» на рабочем столе папки отмечены `/`: щелчок открывает папку, строка «.. Назад» поднимает на уровень выше (показываются первые 8 строк). Старый плоский диск `GBF1` переводится автоматически при первой загрузке: ваши файлы уезжают в `/home` (библиотеки — в `/lib`), встроенные ставятся заново.

Оболочка в духе bash: Shift и Caps Lock на клавиатуре, стрелки вверх/вниз листают историю (16 строк), Backspace стирает. Кавычки `"..."` и `'...'`, переменные `NAME=value` и `$NAME` (`set` показывает все), `;` между командами, `#` — комментарий, `>` и `>>` пишут вывод в файл Grid Store, `cmd1 | cmd2` передаёт вывод следующей команде (фильтры `grep WORD`, `wc`, `head N`, а также `cat` без аргумента), `NAME &` запускает программу в фоне, `sh FILE` выполняет скрипт построчно. Примеры:

```
X=hello; echo "$X world"
echo one > f1; echo two >> f1; cat f1
ls /bin | grep ticker | wc
echo 'echo hi-$X' > s1; sh s1
ticker &
```

## Редактор `edit`

`edit ФАЙЛ` открывает полноэкранный редактор; если файла нет, он будет создан при сохранении.

- стрелки, Home/End, PgUp/PgDn — движение курсора; Enter разбивает строку, Backspace/Delete удаляют, Tab вставляет 4 пробела;
- Ctrl+S — сохранить в Grid Store (до 64 КБ), Ctrl+Q или Esc — выход (при несохранённых правках нужно нажать ещё раз);
- нижняя строка состояния: имя файла, `[+]` при изменениях, `Ln:Col`; сверху — заголовок окна;
- подсветка по расширению: `.c`/`.h`, `.asm`/`.s`, `.sh` — ключевые слова выделены, комментарии, строки и числа своим цветом.

Копирование и вставка (Ctrl+C/X/V, Shift+стрелки) — см. «Вставка текста» ниже.

## genesis в браузере

**Ссылка: https://ivano82ff-eng.github.io/genesis/**

Открывается на компьютере, телефоне, планшете и телевизоре, ничего ставить не нужно. Страница запускает эмулятор [v86](https://github.com/copy/v86) (BSD-2-Clause), а в нём — 32-битную (i686) сборку genesis: v86 не умеет long mode, поэтому для браузера ядро собирается ещё и под i686. Рабочий стол «Ядро» открывается сам; на вертикальном экране — в портретном виде 480x800.

- **Мышь и касания:** щелчок или касание по экрану — щелчок мыши в genesis.
- **🎮** — кнопки на экране: стрелки, OK (Enter), Esc, Tab, ⌫ и RU/EN. На телефоне они включены сразу. Пульт телевизора тоже ходит по ним стрелками и OK.
- **⌨** — вызывает обычную клавиатуру телефона для набора текста, русские буквы тоже.
- **⛶** — во весь экран.
- Диск на 32 МиБ хранится в браузере (IndexedDB): файлы переживают перезагрузку страницы. Чтобы начать с чистого диска, очистите данные сайта.
- `?shell` в конце ссылки оставляет текстовую оболочку без стола, `?size=1280x720` задаёт размер стола.

Сборка и проверка у себя:

```
npm run web           # build/i686/genesis.iso -> web/, плюс v86 и BIOS в web/v86/
npm run test:i686     # все тесты на qemu-system-i386 (32-битная сборка)
node dist/src/cli.js show --arch i686   # 32-битный образ в окне QEMU
```

Сайт собирает и публикует `.github/workflows/pages.yml` при каждом пуше в `main`, перед этим headless Chromium проверяет, что стол открылся. Что отличается в i686: 32-битные страницы по 4 МиБ для ядра и 4 КиБ для программ, без NX (запрет исполнения стека есть только в 64-битной сборке), программы получают аргументы на стеке (cdecl), библиотеки собираются как 32-битный PIC.

## Windows

Команды из этого файла запускайте в WSL (Ubuntu), не в PowerShell. QEMU, GCC, GRUB и Node ставятся внутрь дистрибутива WSL. Снимки экрана открывают окно QEMU, поэтому нужен дисплей: в WSL это WSLg, и `echo $DISPLAY` не должен быть пустым. Это касается тестов VGA, команды `show` и кнопки «Запустить». Проверка одного только serial окно не открывает.

Без WSLg (WSL 1, переменная $DISPLAY пуста) команда `show` (`npm run look`) сама запускает QEMU для Windows: `C:\Program Files\qemu\qemu-system-x86_64.exe` (поставить: `winget install SoftwareFreedomConservancy.QEMU`). Окно открывается на рабочем столе Windows, QMP идёт через TCP на 127.0.0.1. Другой бинарник QEMU можно задать переменной `GENESIS_QEMU`. Тесты по-прежнему используют QEMU внутри WSL без окна.

## Тест

```bash
npm test
```

Тест сам поднимает QEMU, проверяет serial и снимки и сам же его останавливает. Он не ждёт, пока кто-то закроет окно, и не заменяет команду просмотра.

Проверяется маркер на COM1, текстовый VGA, клавиша `a`, `help`, `mem`, файлы, `run hello`, `poweroff`, `reboot`, установка на диск и загрузка без CD, русские кнопки домашнего экрана и «Назад», часы, редактор, `edit` и `cat` после новой загрузки того же диска, `say hello-link` между двумя гостями и фоновая задача `spawn ticker`, пока оболочка отвечает на `ps` и `help`.

Эквивалент проверки маркера без test runner, тоже с ограничением по времени и без окна:

```bash
node dist/src/cli.js test --timeout 20
```

Коды выхода CLI: 0 — маркер есть, 1 — нет, 2 — ошибка сборки, нет программ на хосте или неверные аргументы.

## Пакеты (`pkg`)

Сети TCP/IP нет, поэтому «репозиторий пакетов» — это папка `packages/` в проекте. Каждый пакет — `packages/<имя>/` с `pkg.json` (имя, версия, зависимости, описание), исходниками `.c` и заголовком `.h` для тех, кто его использует. При сборке (`npm run build`, `npm run look`, тесты) хост собирает каждый пакет в плоский позиционно-независимый бинарник и вшивает репозиторий в образ ядра (`build/pkgrepo.bin`). Ничего из него не занимает место на диске, пока пакет не установлен.

```
pkg list               # все пакеты в репозитории, версии, зависимости, [installed]
pkg install strdemo    # ставит strdemo и его зависимости strlib и mathlib в Grid Store
run strdemo            # пример программы, вызывающей функции strlib и mathlib
pkg installed          # что установлено
pkg remove strdemo     # удаляет; удалить библиотеку, нужную другому пакету, нельзя
```

Связывание во время выполнения: программа получает третий аргумент `sym(lib, name)` и по нему получает адрес функции установленной библиотеки или 0, если библиотеки нет. Тогда программа может вежливо сообщить об ошибке, а не упасть. Библиотека — это файл с меткой `GLIB` и функцией `lib_lookup`. Ядро отображает её в адресное пространство программы при первом обращении, а `lib_lookup` выполняется уже в кольце 3. Пример есть в `packages/strdemo/strdemo.c`, а общие макросы лежат в `packages/genesis_pkg.h`.

Ограничения: каждый пакет — один файл в Grid Store; программы ставятся в `/bin`, библиотеки в `/lib`. Всего в каталоге 256 мест (файлы и папки), около 19 занимают встроенные. Перед установкой `pkg` проверяет, хватит ли места, и иначе ничего не ставит. Версии только информационные, обновления и выбора версий нет. Код пакетов и программ выполняется в ring 3 с защитой памяти (см. «Защита памяти»).

## Компилятор C (`cc`)

Внутри genesis есть свой компилятор C (`kernel/cc.c`). `cc ФАЙЛ.c` (или
`run ФАЙЛ.c`) компилирует программу в байт-код genesis и сразу запускает её в
песочнице: каждое обращение к памяти проверяется, бесконечный цикл
останавливается, ядро не страдает.

```
cc /docs/hello.c       # hello from C, 2 + 3 = 5
cc /docs/fib.c         # рекурсия, массивы, указатели
edit /home/my.c        # написать свою, Ctrl+S, затем cc /home/my.c
```

Язык: `int`, `char`, `void`, указатели, массивы, функции (рекурсия, любой
порядок), `if/else`, `while`, `do/while`, `for`, `break/continue`, `return`,
`sizeof`, приведения, `?:`, все обычные операторы, включая `+=` и `++`.
Библиотека: `printf` (`%d %i %u %x %c %s`, ширина), `putchar`, `puts`,
`malloc`, `free`, `strlen`, `strcmp`, `strcpy`, `memset`, `exit`.
Пока нет: `struct`, `float`, `switch`, препроцессора (строки `#` пропускаются).

## Защита памяти

Программы с диска (`run`, `spawn`, `NAME &`) работают в кольце 3, каждая в своём
адресном пространстве. Ядро отображено только для супервизора, у программы своя
память: код с `0x8000010000`, стек (без права исполнения) под `0x8000800000`,
библиотеки `pkg` подгружаются в её же пространство с `0x8000400000`.

- Вызовы `print`, `sleep` и `sym` — это заглушки, которые делают системный вызов
  `int 0x80`. Ядро проверяет каждый указатель: он должен лежать в памяти программы.
- Сбой программы (page fault, GPF, деление на ноль, неверная инструкция и т. п.)
  останавливает только её задачу:
  `task 1 (crashy): page fault at 0x0 (write, kernel memory) ... - task stopped, system OK`.
  На столе «Ядро» на 3 секунды краснеет, а в «Ленте» появляется красная карточка «сбой».
- Сбой в самом ядре по-прежнему останавливает систему с сообщением `KERNEL PANIC`.
- Память задачи возвращается при выходе, сбое и `kill`; `mem` показывает `user pages N/4096`.

Попробовать:

```
run crashy null      # запись по адресу 0
run crashy kernel    # запись в память ядра
run crashy div       # деление на ноль
run crashy op        # неверная инструкция
run crashy sys       # подсунуть ядру указатель на его память
spawn crashy loop    # вечный цикл; ps, потом kill 1
mem                  # user pages 0/4096 после выхода всех задач
```

Ограничения: просмотрщики файлов (`open`, `vtxt`, `vimg`, …) пока работают в кольце 0;
библиотеки отображаются целиком с правом записи (код и данные у них в одном блоке);
состояние SSE между задачами не сохраняется; `run` с вечным циклом держит оболочку —
такие программы запускайте через `spawn`.

## Сеть (TCP/IP)

Карты: RTL8139 и NE2000 (PCI). Стек опрашивается без прерываний: ARP, IPv4, ICMP, UDP, DHCP, DNS, TCP (простой, одно окно — для текста и небольших страниц).

Команды: `dhcp`, `net` (= `ifconfig`), `net set IP MASK GW DNS` (статический адрес), `ping ХОСТ`, `dns ИМЯ`, `http http://хост[:порт]/путь`, `nc ХОСТ ПОРТ ТЕКСТ`, `udp ХОСТ ПОРТ ТЕКСТ`. В программах `cc`: `tcp_connect("хост", порт)`, `tcp_send(s, buf, n)`, `tcp_recv(s, buf, max)`, `tcp_close(s)`.

- **QEMU:** `qemu-system-x86_64 -cdrom build/genesis.iso -netdev user,id=n0 -device ne2k_pci,netdev=n0` (или `-device rtl8139,netdev=n0`). Затем `dhcp` → 10.0.2.15, хост виден как 10.0.2.2, DNS 10.0.2.3. Пример: `ping 10.0.2.2`, `http http://10.0.2.2:8000/`.
- **Браузер (сайт):** карта NE2000 включена сама, v86 изображает роутер 192.168.86.1. `dhcp`, потом `ping 192.168.86.1`, `http http://example.com/`. HTTP превращается в `fetch()` браузера, поэтому работает только с сайтами, которые разрешают CORS; на https-сайте запрос идёт по https. `http://ПОРТ.external/` — это `localhost:ПОРТ` компьютера (для локальной отладки). `?net=0` — без сети, `?relay=wss://…` — настоящий сетевой relay.

Ограничения: TCP без окна и без повторной сборки сегментов не по порядку; только HTTP (без HTTPS/TLS); в браузере без relay доступен только HTTP на порт 80 (ping — только до роутера, `nc`/`udp` наружу не ходят).

## Вставка текста

- **Браузер (сайт, v86):** Ctrl+V (или Shift+Insert) вставляет текст из буфера обмена компьютера прямо в genesis — переводы строк, табуляции и кириллица сохраняются. На телефоне: кнопка «Вставить» справа сверху (или долгое нажатие в поле клавиатуры ⌨ → «Вставить»).
- **QEMU:** у окна QEMU нет общего буфера обмена. Текст можно положить файлом в папку импорта (см. выше) или набрать. Для длинного текста в QEMU из консоли монитора: `sendkey` по одной клавише — неудобно, поэтому лучше импорт.
- **Внутри genesis (редактор `edit`):** Shift+стрелки — выделить, Ctrl+C — копировать, Ctrl+X — вырезать, Ctrl+V — вставить. Без выделения Ctrl+C/Ctrl+X берут текущую строку целиком. В терминале Ctrl+V вставляет внутренний буфер в командную строку.

## Русский язык

Весь текст в genesis — UTF-8: файлы, оболочка, вывод на COM1.

- **Раскладка:** `Ctrl+Пробел` или `Alt+Shift` переключает Latin / Русская (ЙЦУКЕН). В текстовой консоли справа вверху видно `RU`/`EN`, в редакторе `edit` — в строке состояния.
- **Шрифт:** `kernel/cyr8x8.h` — А–Я, а–я, Ё/ё, « » — №. Рабочий стол рисует их сам; в текстовом режиме VGA ядро при загрузке кладёт те же глифы в шрифт карты (слоты CP866).
- **Редактор** `edit` двигает курсор и стирает по символам, а не по байтам. `vtxt` и `cat` показывают кириллицу, в том числе из файлов в `import/`.
- Попробовать: `Ctrl+Пробел`, набрать `echo Привет мир`, затем `write ru.txt Ёлка` и `cat ru.txt`.
- **Куда печатать:** после `genesis>` мигает курсор, при загрузке в первой строке есть подсказка. На рабочем столе внизу — строка команд с тем же приглашением и мигающим курсором: набранная команда выполняется по Enter, первая строка ответа видна под ней.

## Браузер

Ячейка «Браузер» (глобус) на столе, или команда `browse АДРЕС`. Открывает:
`http://…` (через TCP/IP; `https://` идёт как http), файлы с диска
(`/docs/index.html`, `file:///docs/web.html`, папка → список ссылок),
`about:home`, `about:help`, `about:blank`. На диске лежат тестовые страницы
`/docs/index.html` и `/docs/web.html` — браузер работает и без сети.
`.html`-файл из «Файлов» тоже открывается в браузере.

HTML: заголовки, абзацы, списки (`ul`/`ol`), ссылки, `pre`, `br`, `hr`,
`img alt`, сущности (`&amp;` …). Скрипты, стили, `svg`, `iframe` выбрасываются.

- **Мышь / касание:** щелчок по ссылке; «Обновить»; ^ / v — прокрутка;
  щелчок по адресу кладёт его в строку внизу.
- **Клавиатура / пульт:** Tab или стрелки — по ссылкам, Enter — открыть;
  без фокуса ↑/↓ и PgUp/PgDn прокручивают; адрес набирается в строке внизу + Enter.
- **Назад** (Backspace, кнопка «<», «< Назад» на телефоне) — ровно на одну
  страницу назад; на первой странице закрывает окно. **Esc** / X — закрыть сразу.
- **Оболочка:** `browse URL`, `web back`, `web reload`, `web follow N`.
  В текстовой консоли страница печатается текстом со ссылками `[N]`.
- **Ошибки** (нет сети, нет файла, 404) — страница «Страница не открылась».

Ограничения: без HTTPS/TLS, CSS и JavaScript; только UTF-8; до 5 переадресаций,
история — 16 страниц. На сайте (v86) — только HTTP на порт 80 и только сайты с CORS
(`http://ПОРТ.external/` — localhost компьютера); перед этим `dhcp`.

## Ячейки вокруг ядра

Порядок и набор ячеек настраивается и хранится в `/home/.layout`
(по ключу в строке, `-ключ` — скрыта); при загрузке восстанавливается.
Ключи: `files editor term pkg mem feed set web`, `app:ИМЯ`, `pin:/ПАПКА`.

- **Правка:** «Настройки» → «Ячейки: правка», команда `layout edit` или долгое
  нажатие на ячейку (мышь/касание, ~0,6 с). Ячейки становятся янтарными.
  - мышь / касание: перетащить ячейку на место другой;
  - клавиатура / пульт: Tab/стрелки — выбрать, Enter — взять, стрелки — двигать,
    Enter — положить, `x` — убрать;
  - Esc, Backspace или щелчок по ядру — готово.
- **Команды:** `layout` (`list`), `layout move ИМЯ ПОЗ`, `layout remove ИМЯ`,
  `layout add ИМЯ` (вернуть скрытую; `layout add /папка` закрепит папку),
  `layout reset`. ИМЯ — ключ или подпись (`web`, `Браузер`, `Память`).

Ограничения: не больше 12 ячеек; `layout add` возвращает только известные
ячейки (встроенные, установленные программы) или закрепляет папку.

## Стол «Ядро»

`desktop` открывает «Ядро»: в центре светится шестиугольное ядро (память и
фоновые задачи, обновляется раз в секунду, краснеет при куче > 85%), вокруг
соты программ. Щелчок по ядру — список задач с кнопкой «стоп» (`kill N`).
`pkg install` добавляет соту программы, `pin ПАПКА` / `unpin ПАПКА` — соту
папки (`/home/.pins`). Строка внизу выполняет любую команду, подсвечивает
подходящую соту, Tab дополняет команды и пути, PgUp/PgDn листают историю.

- **Где что:** ядро стоит по центру над строкой команд, соты — ровным
  кольцом вокруг (первая сверху, левая и правая половины зеркальны). Когда
  справа открыта панель, кольцо сдвигается в свободную часть экрана.
- **Часы** берут время из CMOS RTC и идут; по умолчанию UTC+3, `tz +5`,
  `tz -3:30`, `tz` — показать пояс. **Память** в ядре — реальная доля
  занятой RAM (ядро ОС + куча) от свободной памяти из карты Multiboot.
- **Стрелки:** первая стрелка ставит фокус на ядро, дальше ←↑→↓ ходят по
  сотам (и по клавишам цифрового блока без NumLock — так их шлёт QEMU на
  Windows). В открытой панели фокус сразу на первой строке, ←/→ уходят из
  панели к сотам и обратно, Enter — открыть, Esc — закрыть.
- **Лента:** журнал всех действий (`/home/.journal`, последние 40):
  команды, открытые/сохранённые файлы, `pkg install/remove`, запуск и
  остановка программ. Сота «Лента» (или `feed`, `feed pkg|files|editor|term|prog`)
  открывает линию времени с карточками и светящейся отметкой «Сейчас»;
  стрелки ходят по карточкам и листают, Enter открывает файл снова или
  повторяет команду (для `rm`, `pkg remove`, `kill`, … — второй Enter,
  Esc — отмена). Сверху фильтры: Все, Файлы, Редактор, Терминал, Пакеты,
  Программы. В каждой панели есть кнопка «В ленту» — Лента сразу с фильтром
  этой панели. На телефоне линия вертикальная.
- **Связи:** когда программа берёт функцию из библиотеки, на секунду-две
  вспыхивает линия от её соты к соте «Пакеты» (у библиотек своей соты нет),
  а пока программа работает — линия к ядру (`link: strdemo -> strlib`).
- **Сосед по Genesis Link:** если вторая genesis ответила (`ping`), слева
  вверху появляется маленькое ядро «СОСЕД». Щелчок/Enter по нему — выбрать
  файл в /home, и он уйдёт соседу в `/home/inbox/` (кусками по 112 байт с
  подтверждением каждого и контрольной суммой). Из оболочки: `send ФАЙЛ`.

- Телефон: `desktop 480x800` (или `npm run look -- --portrait`) — ядро сверху,
  соты сотами внизу, панели на весь экран с кнопкой «< Назад».
- Телевизор: `desktop 1920x1080` (`npm run look -- --tv`) — крупный текст;
  всё делается пультом: стрелки двигают жёлтую рамку фокуса, Enter открывает,
  Esc/Backspace — назад.
